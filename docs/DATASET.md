# 数据格式与标注

## 重要说明

原始采集数据 **不在本仓库中**。训练脚本需要你自己按下面的格式准备数据；仓库只提供格式约定和脚本。

数据可能包含个人运动轨迹与生活习惯，公开前请脱敏，并确认所有参与者知情同意。

## 目录组织

脚本会递归扫描数据目录下的所有 `.csv`，按以下规则打标签：

1. 如果 CSV 里有 `Train_Label` 列，直接使用；
2. 否则看文件路径（不区分大小写）：
   - 包含 `WALK` → 1（步行）
   - 包含 `BYCLE` 或 `CYCLE` → 2（骑行）
   - 包含 `RUN` → 3（跑步）
   - 其他 → 0（其他）

推荐目录：

```text
train_data/
├── WALK_20260101/
│   ├── 001.csv
│   └── 002.csv
├── RUN_20260102/
├── BYCLE_20260103/
└── OTHER_20260104/
```

`Sample_Block` 列用于区分连续采样块；没有该列时整个文件视为一个块。

## CSV 列

12 维模型需要以下列（列名允许前后空格；`vert_perce` 这类被截断的表头会被模糊匹配）：

| 列 | 含义 | 单位 |
|---|---|---|
| `roll` | 横滚角 | 度 |
| `pitch` | 俯仰角 | 度 |
| `accel_x/y/z` | 东北天坐标系加速度 | g |
| `gyro_x/y/z` | 角速度 | °/s |
| `vert_line_accel` | 竖直方向线性加速度 | g |
| `accel_mag` | 三轴加速度模长 | g |
| `hor_accel` | 水平方向加速度强度 | g |
| `vert_percent` | 垂直占比 | 比例 |

13 维模型额外需要 `yaw`，并在 `SW_define.h` 中把 `TF_LITE_USE_PARAMETER_13` 设为 1。

可选的列：`Train_Label`、`Sample_Block`、`timestamp`、`quat_w/x/y/z`。

## 窗口与类别

- 窗口长度：75 帧；步长：40 帧
- 同一窗口内标签必须一致，否则丢弃
- 类别：`0 其他 / 1 步行 / 2 骑行 / 3 跑步`

窗口参数在 `training/Quantization_Conv1D_LSTM.py` 的 `create_time_windows(..., window_size=75, step=40)` 中。

## 采集建议

- 每个类别至少覆盖不同速度、不同佩戴位置和不同人；
- 保留静止/其他类作为负样本，避免模型把所有活动都归到三类运动；
- 训练集、验证集、测试集按 **采集段** 划分，不要按窗口随机划分，否则同段数据泄漏会虚高准确率；
- 记录设备型号、固件版本和采样率，便于复现。
