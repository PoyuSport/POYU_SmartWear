# 测试前端：微信小程序「Poyu Sport」

固件本身只负责采集、推理和 BLE 通信。要快速验证板子是否正常工作，推荐直接用配套的微信小程序 **「Poyu Sport」** 作为测试前端。

> 小程序是闭源的配套工具，不在本仓库中；本仓库只保证 BLE 协议和广播参数与它兼容。也可以使用 nRF Connect、LightBlue 等通用 BLE 工具代替。

## 连接参数

| 项目 | 值 |
|---|---|
| 广播名称 | `POYUSPORT` |
| Service UUID | `4fafc201-1fb5-459e-8fcc-c5c9c331914b` |
| Characteristic UUID | `beb5483e-36e1-4688-b7f5-ea07361b26a8` |
| 属性 | Read / Write / Notify |
| 数据方向 | 设备 → 手机：Notify；手机 → 设备：Write |

固件会同时使用两种上行格式：

1. 文本行：`poyu#<内容>\n`（兼容旧版小程序/调试）；
2. 二进制 TLV 帧：`0xAA 0x55` 开头，格式见 [protocol.md](protocol.md)。

## 测试步骤

1. **烧录固件**，确认串口日志里 BLE 已启动、设备正在广播。
2. 手机打开蓝牙；Android 还需要授予微信「附近设备/位置」权限，否则扫不到设备。
3. 微信 → 发现 → 小程序，搜索 **「Poyu Sport」**；如果搜不到，使用维护者提供的小程序码，或在仓库提 issue。
4. 进入小程序，授予蓝牙权限，扫描并选择 `POYUSPORT`。
5. 连接成功后确认已订阅 Notify，观察实时数据/连接状态。
6. 按小程序当前版本的界面进行录制、查看或断开；具体功能以小程序实际版本为准。
7. 测试结束在小程序内断开，或直接给板子断电。

## 常见问题

| 现象 | 排查 |
|---|---|
| 扫不到 `POYUSPORT` | 确认板子已广播；Android 检查微信定位权限；确认没有被另一台手机占用；重启蓝牙/板子 |
| 连上但无数据 | 确认订阅了 Notify；确认 Characteristic UUID 正确；看串口是否有发送日志 |
| 收到乱码 | 区分文本 `poyu#...` 和二进制 `AA 55` 帧；二进制请按 [protocol.md](protocol.md) 解析 |
| iOS 搜不到/名称不更新 | 关闭再打开蓝牙；忽略旧设备后重新扫描 |
| 小程序搜不到但 nRF Connect 能连 | 小程序版本或权限问题；先用通用 BLE 工具确认服务和特征是否正常 |

## 用通用 BLE 工具代替

如果暂时没有小程序，可以用 nRF Connect / LightBlue：

1. 扫描 `POYUSPORT` 并连接；
2. 找到 Service `4fafc201-...`，打开 Characteristic `beb5483e-...`；
3. 打开 Notify；
4. 观察十六进制数据：文本行以 `70 6f 79 75 23`（`poyu#`）开头；二进制帧以 `AA 55` 开头。

## 边界

- 小程序不随本仓库开源，仓库不包含它的安装包或 AppID。
- 小程序面向的是运动/羽毛球业务界面；本固件是通用运动识别参考实现，二者字段并非一一对应，测试时以“能连接、能收到数据、能断开”为主要目标。
- 若你修改了广播名称、UUID 或协议，需要同步修改小程序或改用通用 BLE 工具。
